## 2. 输入

每条输入四个字段：`item_id`、`target`、`title`、`text`。帖子没有标题，`title` 为空。

- 同一段文字涉及多个标的时，每个标的各是一条输入，分别判断。代码不做“看多某公司 → 看多 QQQ”的转换。
- 标的名称是提示词的一部分，计入推理身份。

**现状的限制**：标的只有现有词表里的四个——QQQ、存储芯片板块、科技与半导体板块、美股整体市场。NVDA、美光这类公司级标的还没有进入词表，库里也没有新闻。合约本身支持任意标的和带标题的新闻（探针里用美光和一条带标题的新闻验证过），但真实数据只验证了帖子。

## 4. 实现

| 要求 | 实现 |
|---|---|
| 固定版本与确定性解码 | 提示词、模型、生成参数、标的名称都计入推理身份；任何一项变化都是新身份 |
| JSON 约束 | 当前后端没有语法约束解码。做法：助手回合以 `{` 开头，读到闭合括号为止，然后严格解析和校验，不修补 |
| 重试 | 超时或格式错误最多重试一次，记录尝试次数和原因；再失败记为“分类失败”，不填成中性。贪心解码下，格式错误的重试通常得到相同输出，对超时才真正有用 |
| 保存 | 模型原始输出、分类结果、标的、版本、真实开始和完成时间 |
| 复用 | 相同文本、标的和推理配置不再重复请求（测试：第二次导出为 0 条） |
| 过长文本 | 超过 4,000 字符的不送模型，记录为截断，单独计数；不会截掉后半段还当作读完 |
| 文本中的指令 | 提示词声明文本不可信；代码不执行任何文本内容。**但模型本身不保证不受影响，见第 6.3 节** |

校验后的状态只有四种：有效（看多 / 看空 / 中性）、无关、分类失败（格式不符）、分类失败（引用的依据不在原文）。依据允许为空；不为空时必须逐字出现在标题或正文里（只忽略空白差异）。

## 5. 页面与统计（已实现，未发布）

新增“模型判断”标签页：

- 每条材料：标的、看多 / 看空 / 中性、简短解释、依据原文、原文链接。
