## B 独立实现（`independent_reference.py`、`independent_rule_tests.py`）

**实现方式**
- 未导入 run.py 或 check.py，也未读取首轮的信号或账本来生成结果。
- 指标、状态机、次日开盘执行、扣费目标方程、现金与单位账本、区间末平仓、指标计算、循环区块抽样、Holm校正和8周Spearman相关都依据协议文字重写。均线等滚动量用显式窗口循环计算，不用pandas的rolling。
- 文件开头列出了9条解释口径（I1–I9），全部与首轮行为一致。
- 区块抽样起点的抽取方式沿用了 `default_rng(seed).integers`，以便逐项比较p值；区块求和、分位数、p值和Holm都是重新推导的。

**全量对账**（330份账本、360行汇总、48行对照、72行因子，均与首轮比较）

|项|最大误差|
|---|---:|
|目标权重|2.2e-14|
|日净收益|1.4e-15|
|NAV（绝对 / 相对）|5.1e-11 / 8.8e-13|
|进场费 / 末端费|9.9e-15 / 4.0e-14|
|终值财富 / CAGR / 最大回撤|3.5e-11 / 4.7e-14 / 5.8e-14|
|对照均值差 / 置信区间 / p值|1.3e-16 / 1.4e-16 / 1.1e-16|

所有误差都在建议容差内（相对1e-10、绝对1e-8）。日期与行数不一致的账本为0份。

**规则检查**：16项全部通过（`logs/B_rule_tests.log`）。
- P2：压力记忆20条；入场信号后第40条退出；按收盘最高值回撤8%止损提前退出。
- P3：每个开盘按目标权重再平衡；扣费后的权重等于目标；末端只收一次平仓费；每个评价期从现金1重新开始。
- 252条暖机：首个可执行开盘是每段第253条，科创50因此从2021-08-04开始。
- SOX按7个缺口日切成5段，其中第2、3段不足252条，不会交易；主评价期不跨越任何片段边界。

**因果性检查**：四个市场各做两次截断前缀和一次未来价格扰动，已过去的信号与因子值变化均为0。小例子的现金守恒和费用解析值也一致。

## C 另一份数据

**数据身份**：E:\moomoo_US_OpenAPI_readonly_setup 中的 history 与 patch 两个归档，SHA256 为 `85aa32f5…b309` 和 `08ff7106…0f170`，正是包内数据库 input_archives 记录的首轮来源。因此属于“同一供应商、同一批数据”，不是不同版本，也没有增加历史或新增未来日期。本机的其他moomoo行情只有早期项目的个股日线（AAPL、AMD等），不含这四个标的。

**实际完成的检查：从原始响应独立重新派生**（`adapt_raw_to_research_db.py`，只读访问归档）
- 规则：
  - 按请求日志取K线，补丁中的 patch_* 只补原始归档缺少的日期，校验类请求不插入数据；
  - 剔除周末日期、科创50发布日（2020-07-23）之前的数据、非正值和OHLC矛盾的行；
  - 缺口只用同市场观测互相对照：QQQ与SOX互查，上证与科创50互查。
- 供应商交易日历把1999-01-01等节假日列为交易日（与QQQ相差26天、与SOX相差53天），因此只作诊断，不用于切片。
- 结果：
  - 30,716行研究日线与包内数据库**逐位完全相同**（日期集合与OHLC）；
  - 推导出的7个SOX缺口与包内完全一致，补丁中供应商对这些日期的复查均返回0条；
  - 科创50的133条发布前数据与下载器标记没有分歧。
- 在派生库上按任务命令执行 `run.py --mode external --end 2026-11-17` 和 check.py：12项通过0项，264份账本与首轮逐字节一致，其余为同样的P3浮点差异。独立实现在派生库上同样一致。

**无法完成的部分（BLOCKED）**：没有新的数据版本，也没有2026-11-17之后的日期，因此新数据验证与前瞻评价都没有执行。要完成真正的C，需要这四个序列（QQQ a1、SOX、上证、科创50）的另一次下载，或者2026-11-17之后的日线。
