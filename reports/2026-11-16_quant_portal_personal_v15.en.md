# Personal Demo v1.5: bilingual technology-event workbench

**Execution date:** 2026-11-16, Asia/Shanghai. **Scope:** the existing owner-only loopback portal, six moomoo quote symbols and Jin10 private flash cache. The financial-text v2.5 candidate remains `REJECTED_CANDIDATE`; no financial fit, return prediction, trading call or public display was made.

## What was implemented

- A Chinese/English choice is stored in each user's preference. The dashboard and live cache text use one UI catalog, with explicit “Translation pending” for material that lacks an English rendering. News source text stays expandable and unchanged; language switching reads the local cache only.
- The homepage defaults to the quote summary and a distinct-event Top 10. News, watchlist/subscription controls, chart, news-tone windows, historical facts and diagnostics each fold independently. Open state is kept in the signed-in browser's account-scoped local storage.
- New Jin10 items are screened before entering the main news table. Include requires an explainable direct company, industry or macro phrase; uncertain items enter a bounded private review queue; excluded items retain a hash and reason but no irrelevant body. The old cache was labeled in place and is hidden by default without deletion. This is relevance screening, not verification of supplier claims.
- A separate single-worker local Qwen queue uses the pinned `Qwen2.5-3B-Instruct` revision `aa8e72537993ba99e69dfaafa59ed015b17504d1`. It keeps raw attempts privately, permits one logged repair, checks strict JSON, fields, numeric tokens and exact quote location, and records failures. A separate response-hash-bound `CODEX_REVIEW` decision gates “complete” cards; a mechanically passing but unreviewed response is not presented as accepted analysis. The model is not a trained price predictor.
- The Top 10 uses fixed, explainable product factors and deduplicates suspected event groups. News-tone windows count those groups over one, six and 24 hours, with unanalysed counts and insufficient-sample flags. Observed market movement remains a separate unavailable field; no price move is attributed to news.

## Actual evidence and limitations

The pre-change online snapshots and 20-item frozen development batch are described in [the freeze receipt](../results/quant_portal_personal_v15_20261116/freeze_redacted.json) and [batch receipt](../results/quant_portal_personal_v15_20261116/analysis_batch_redacted.json). The latter selected 20 distinct groups from 129 scanned recent entries under the first rule version. A subsequent documented relevance-rule correction addressed Chinese-adjacent CPI/HBM matches; [the legacy backfill](../results/quant_portal_personal_v15_20261116/legacy_backfill_redacted.json) labeled 241 saved entries: 30 include, 40 pending, 171 hidden as excluded. Those counts describe this local cache only, not all news.

The first larger-schema model trial stopped after three failed items and is retained in [its negative receipt](../results/quant_portal_personal_v15_20261116/model_trial_v15a_redacted.json). The compact v1.5b frozen-batch [model receipt](../results/quant_portal_personal_v15_20261116/model_run_redacted.json) records **20/20 items attempted, 35 generation calls, 15 items with one repair, eight mechanically complete and 12 failed**. Exact-quote failures dominated the recorded contract errors. [Same-team content review](../results/quant_portal_personal_v15_20261116/semantic_review_redacted.json) checked all eight mechanical completions and **rejected all eight** for mistranslated names, missing quote or unsupported claims. Thus zero model cards were accepted for completed display; the private raw outputs and all failures remain intact. The old code's null-quote completion bug was corrected for subsequent jobs after the frozen batch, without changing its saved results. The batch launch did not separately capture a byte hash of the running Python source; the receipt records this provenance limitation and the source hashes observed at audit. These repeatedly used development messages are no independent accuracy set.

The [current owner-only runtime receipt](../results/quant_portal_personal_v15_20261116/runtime_redacted.json) returned six quote rows and ten Top 10 positions, while moomoo and Jin10 collector heartbeats remained live. A separate analysis worker was restarted after the bounded batch to process later eligible messages; its queue and status are live values, not part of the 20-item result. A new quote-cache lookup removed a slow correlated scan; its real readback took about 0.045 seconds at the measured cache size. This is one local performance observation, not a load guarantee. [Focused Python checks](../results/quant_portal_personal_v15_20261116/focused_tests.log) passed 37/37; [Django account-isolation checks](../results/quant_portal_personal_v15_20261116/django_tests.log) passed 5/5; [JavaScript syntax](../results/quant_portal_personal_v15_20261116/js_syntax_checks.log) passed for four files. These are software checks, not model or news accuracy. The portal and collection service were restarted/read back on the local loopback address.

**Visual acceptance:** `NOT_RUN`. The computer-use tool stopped because it could not establish the Windows browser URL with sufficient confidence. Thus desktop and 390px behavior was not visually confirmed in this round. Existing v1.4 visual results do not certify the new layout. Static code and HTTP checks are reported separately.
