## 2. Initial suggestion versus executed configuration

The user reports an initial suggestion of **252 common trading days and PCA K=3**. A search of the current repository's config, roadmap, task ledger and reports found no stored `252` or `K=3` M4 setting or rationale. Accordingly, this suggestion is attributed to the user's stated prior plan, not to a versioned local config. The actual `configs/m4_demo.yaml` set **2025-01-01 through 2025-12-31 inclusive** and `pca.components: 2`; the M4 run manifest records that config hash. These were engineering-demo choices made before the real run, not approved formal research parameters.

The raw Massive responses contain **250 daily bars for each of the five fixed securities**, all on the same 250 dates. The 2025 calendar window has 261 weekdays; 11 absent weekdays correspond to ten standard market holidays plus the additional 2025-01-09 National Day of Mourning closure. Thus a generic 252-day convention does not describe this exact calendar window. The standard 2025 holidays are listed by [NYSE](https://www.nyse.com/markets/hours-calendars); [Nasdaq's market-operations notice](https://www.nasdaqtrader.com/TraderNews.aspx?id=ETA2024-87) confirms the January 9 closure. The raw date list and the calendar comparison are in the evidence package. This calendar check explains the count; the authoritative observed price count remains the saved Massive pages.

The close-to-close formula requires a previous price. The first bar is 2025-01-02, so its return is missing; **249** dates have complete returns. The full return matrix is **250×5**, with five explicit missing cells and no zero-fill. PCA uses the **249×5** complete past-window submatrix, producing **5×2** stock loadings and **249×2** date scores. The centered matrix has effective rank **5**, so K=2 was **not forced by rank**; the repository records no stronger scientific justification for choosing 2 instead of the user-stated 3. This is a protocol deviation to resolve in M5, not a reason to edit the saved config or output. All counts, shapes and rank are traceable to `common_masks.json`, `missing_exclusions.json`, `pca_metadata.json` and the self-audit receipt.

## 3. Exact status of the audit

`scripts/audit_m4_run.py` was authored and executed by the **same Codex agent** that implemented and ran M4. It is a **separately coded, read-only self-audit**, not an independent researcher review. It reads the saved SEC corpus index, ten raw Massive response JSON files and their receipts, identity/bar JSON, M4 manifest, return array, masks and PCA metadata/arrays. It verifies 7 input hashes, 42 output hashes and 11 source-file hashes; matches ticker/CIK and bar fields; rebuilds the union-date close-to-close return matrix with its missing mask directly from raw `c` and `t`; recomputes mean, effective rank and singular values; and checks the score/loading relation and shapes. It does not import or call `finembed.m4.return_matrix`, `past_pca` or `parse_bars`.

Both implementations share the M4 scope, saved source data, close-to-close definition, date window and the expectation of centered/unscaled PCA. The check can catch implementation and transcription errors, but it cannot establish that those scientific choices are correct, that the vendor's historical revisions were frozen, or that no future information leaked. No external auditor signed the receipt. The older receipt with less precise wording is retained; `...-selfaudit-v2.json` explicitly labels the check as same-agent self-audit and records its script SHA-256.
