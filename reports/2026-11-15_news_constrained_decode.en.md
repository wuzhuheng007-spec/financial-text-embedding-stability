## What the compiler check establishes

The attachment's nine listed files matched their SHA-256 and size manifest on extraction. The integrated [compiler code](../scripts/news_constrained_decode_v1/compile_wire_v2.py) only accepts the pinned original wire-v2 bytes (SHA-256 `afc517b5…`). It expands the root's four dispositions by three market-outcome states and the record's three conditional predicates into eight alternatives. It retains required fields, finite enums, array lengths and `additionalProperties` in its candidate. The candidate's SHA-256 is `f7bc9df682ca365131c0b97592bfa4bc0beaf23ad63a6c90dc1d67007cec4c5f`. The 4,573 tested objects cover a finite combination set and mutations; the [37 backend sentinels](../results/news_constrained_decode_20261115/compiler_gate_run1/backend_sentinels.json) are test inputs rather than news or model outputs.

The original Schema and the candidate were compared using `jsonschema`, which cannot show that a token-filtering backend implements every `anyOf`, `$ref`, array bound, string bound, or cross-field restriction. The original wire validator and quote/canonical checks remain the acceptance path. Any backend acceptance of an object rejected by the original wire validator is a gate failure; no response will be repaired or relabeled to pass.

## Backend compatibility decision

The [locked LM Format Enforcer 0.11.3 candidate](../configs/news_n1_lmfe_backend_v1.lock.json) was installed into an isolated dependency target from the [official PyPI release](https://pypi.org/project/lm-format-enforcer/0.11.3/); pinned `torch`, `transformers`, `tokenizers` and model weights were unchanged. The [default-limit probe](../results/news_constrained_decode_20261115/backend_probe_limits_default.json) observed 20-item array and 12-consecutive-whitespace settings, with five tested source-valid serializations rejected. Explicit array/whitespace settings plus the fixed tokenizer alphabet removed those **character-level** mismatches: the [compatibility receipt](../results/news_constrained_decode_20261115/backend_compatibility_receipt.json) records 63/63 matches to the original Schema, comprising 29 accepted and 34 rejected cases, without unsupported-keyword warnings.

The actual Transformers prefix callback with the pinned Qwen tokenizer accepted one valid no-record sequence through 74/74 tokens and both EOS IDs, and rejected the invalid market-direction sequence at token 40/182. It also disallowed the tested token sequence for three source-valid synthetic objects: a company event at token 79/184, a Unicode/escape case at 75/196 with an empty allowed-token set, and a 21-evidence case at 363/468. All tested token sequences decoded back to their input text. These witnesses establish failure of this tested callback path; they do not prove the objects are unreachable under every equivalent JSON serialization. A spaced/escaped alternative probe yielded no result after about 165 seconds and was stopped without a model call, leaving alternative reachability **UNKNOWN**. The source contract could not be shown enforceable within this gate, so no v6 model run began.

A separately versioned alternative could split article-level disposition from company-event evidence records, then compose a complete wire object and submit it to the unchanged original validator. That would change the extraction procedure and needs its own object-coverage, tokenizer and cost gates before a model call. This is a design candidate, not an implemented fix or a relaxed acceptance rule.

## Bounded interpretation and next decision

The prior v5 run's nine error instances were four `market_outcome_direction:const`, two `records[].evidence_spans:minItems`, two `records[].unknown_reason:enum`, and one `records:maxItems`, according to the [audited aggregate](../results/news_targeted_repair_20261115/inference_aggregate.json). These are instances among six JSON-valid responses, not nine articles. The [saved-evidence recheck](../results/news_constrained_decode_20261115/v5_evidence_recheck.json) confirms the four market-direction values were strings but keeps their labels private; the two evidence arrays each had one span where at least two were required, both unknown-reason values were JSON null, and the offending records array had one item where none was allowed. Timeout positions 4, 7 and 9 last reached `GENERATION_STARTED`; their attempt wall times were 181.406, 181.516 and 182.406 seconds, including startup and timeout overhead. Before generation, the saved CUDA free-byte values were 968,671,232; 1,183,363,072; and 1,595,129,856 respectively. No intermediate token counts or interval timing were saved. The seven completed responses' `AFTER_GENERATION` snapshots all returned `free_bytes=0`. A later host check found 9,373 MiB free with five compute-process rows. These observations do not establish an OOM or timeout cause. The new backend may add processing time within the unchanged call limits.

One successful decoder format would describe this pipeline on reused development articles. It would not measure company identity, event semantics, impact direction, evidence sufficiency, or predictive value. The assigned reviewer can now use the click-only article screen; it has no saved selections yet. Its article-level choices will not supply per-company event and quote gold without a later versioned human review. Extraction-quality metrics remain **NOT_RUN**. Historical security identity, accepted market-time and price rules, independent event-grouped holdout evaluation, financial labels, fitting, predictions and return assessment remain **NOT_RUN / NOT ADMITTED** as applicable.
