## 二、QQQ 三页试点（已实现，未启用，未发任何付费请求）

**做法**
- 常规每两小时的第一页不变，就是同一时间窗的对照。
- 只有 QQQ 的第一页留下“下一页”游标时，试点在同一轮、同一查询、同一时间窗上，从这个游标接着读第 2、3 页。第一页不会再问一次，同一个窗口只接一次。
- 第 2、3 页及其帖子只写进试点自己的库（生产库旁的 x_stance_page_pilot.sqlite3）。生产库只多出账本记录（作业类型 pilot_pages）。生产样本、分类队列、汇总和新鲜度都看不到试点帖子。
- 每个窗口记一行：第一页返回数、之后读了几页、停在哪里；被上限挡下的窗口记为 SKIPPED，不悄悄丢掉。
- 报告（page_pilot report）按第 1、2、3 页分列，再按英文、中文分开：返回数、相对生产库与前几页的新帖、独立作者、不在同窗第一页的新作者、账本费用。只输出计数。

**额度：保留常规第一页的额度**
- 不改 config 里的 budget / allocation。预检回执绑定了这两块，一改就会让采集闸门关上。
- 试点从 recent 池付钱，不占关键词子额度（2,400 条 / 0.36 美元）。
- 每次试点请求前，在账本同一个事务里检查：这一页之后，recent 池、全作业日上限和滚动上限，仍要够当天剩下每一轮的全部常规请求（8 条关键词、24 个看人账户，每页按容许的 25 条、375 点计，但不超过各自子额度的剩余），外加历史池当天剩下的全部。不够就停到第二天。
- 试点自己的上限（按账本实测定）：每天 36 次请求、0.12 美元；3 个北京时间日合计 108 次、0.30 美元。每次检查都按满页 375 点算，所以只会在上限之前停，不会超过。
- 截止时间在每次联网前检查，重试也一样。
