# M10 local research assistant: architecture and reproduction

M10 adds a source-bound retrieval assistant for **descriptive inspection of exact saved disclosure text**. It is separate from the M2–M7 embedding-stability experiments and the unfrozen M5 financial protocol. The implementation provides a validated-input gate, local LlamaIndex nodes, BM25/dense/hybrid retrieval, a development-question harness, and a separately configured generation contract. A working code path is not itself evidence of a completed run: use each local run's manifest and test logs to establish what was actually executed. No historical trading-time, prediction, return, or financial-value claim follows from a retrieved passage.

## Input and trust boundary

`finembed.validated_inputs.load_validated_input(spec_path, project_root=None)` accepts an explicit version-bound JSON spec and returns `(document, audit)`. The input types are:

| Type | Exact text used | Validation and limit |
| --- | --- | --- |
| `original_extract` | One saved extracted section | Calls the existing `m6.load_sections` exact-substring and file-hash checks for a single-entry section index. This establishes a source-bound extract, not a researcher approval or first-public time. |
| `structured_derivative` | An accepted M9 table-structured Item 2 derivative | Rehashes the raw submission, embedded primary HTML, reproducible primary text, original Item 2 substring, derivative, serializer source/config, table and unchanged-text spans, boundary evidence, acceptance event, prior decisions, private reply, and separate project-validation receipt. The derivative is labeled as transformed text; generated structural labels are not SEC wording. |

The credential-free field layout is in [`configs/validated_input.example.json`](../configs/validated_input.example.json). It is a placeholder, not an accepted input. Real AMZN/GOOGL specs and their receipts are in ignored local `artifacts/m10/20261028T000807Z-loader/`; they rely on the saved M8/M9 source files, which are not redistributed. The read-only loader check recorded both derivatives as `LOADABLE_WITH_LIMITATIONS` in `load_check_receipt.json`. This is a same-agent source/software check, not a new human review, model inference, or financial result.

The acceptance anchor is **not** a hash supplied solely by the spec. `TRUSTED_ACCEPTED_INPUTS` in [`validated_inputs.py`](../src/finembed/validated_inputs.py) pins the exact M9 company/CIK/accession and raw, parent, derivative, provenance, researcher-event, and project-validation hashes for AMZN and GOOGL. The loader also checks the event and receipt semantics. A newly supplied spec or altered decision file cannot authorize itself. To admit another reviewed version: retain its original and correction history, obtain the actual researcher decisions and project-validation receipt for that exact derivative, independently inspect and hash every bound source, add the exact identity and hashes in a code-reviewed change, add positive and tamper tests, and create a **new** spec and index. Never update the trust anchor just to make a failed input pass. GOOGL MDA-1/MDA-5 sparse header-to-value mappings remain explicit limitations.

`audit["validated_files"]` lists the files and SHA-256 values checked by the gate. The index binds and rechecks these files on retrieval, so a changed source, acceptance record, or code file requires a new index. Private researcher-reply files are bound for local integrity but their text and paths must not be placed in node content, answer passages, or a shared export. `review_references` in nodes contain kind/hash only. The returned `document["text"]` is the exact decoded saved input, not review-page text.

## Index and retrieval

Install the optional pinned adapter dependency with `python -m pip install -e ".[embed,rag,test]"`. The `rag` extra pins tested `llama-index-core==0.14.25` and, on Windows, `tzdata==2026.2`; the code checks the exact LlamaIndex core version. The adapter uses LlamaIndex `Document`, `TextNode`, `BaseRetriever`, `BaseEmbedding`, and `NodeWithScore`. It does not silently use a hosted LLM, embedding endpoint, or the LlamaIndex BM25 integration's potentially different scoring defaults.

[`configs/rag_example.yaml`](../configs/rag_example.yaml) is an **engineering RAG configuration**, not a revision of the frozen 128/192-body-token research comparison. It uses the pinned MiniLM tokenizer and encoder from `configs/smoke.yaml`, 160 body tokens per chunk, zero overlap, and a two-special-token check against the model input limit. Chunks have contiguous token coverage and saved character spans. The index refuses mixed form/section strata, including pooling 10-K Business with 10-Q MD&A. Stable document and node IDs incorporate source identity and text version. Node metadata preserves provenance, transformation/limitation labels, token and character spans, and source-table references; it is excluded from both embedding and LLM content. The full filing is not copied into every node.

The local index is written to a **new**, ignored `.cache/` or `artifacts/` directory. Its `manifest.json` binds configuration, tokenizer/model files, source and review records, code hashes, node count, fit boundary, optional dense-model identity, and output hashes. `nodes.jsonl` contains exact chunk text and metadata; `vectors.npy` is present only when `--dense` successfully builds verified chunk vectors. Treat both as local source-derived material. Retrieval refuses a changed binding or altered index file; it never substitutes a lexical result for an unavailable dense branch.

Lexical retrieval uses the project's [`BM25`](../src/finembed/lexical.py) on ASCII alphanumeric, lowercased terms with no stemming or stopwords. In the example configuration, `k1=1.2`, `b=0.75`, and repeated query terms are deduplicated. IDF is `log1p((N - df + 0.5) / (df + 0.5))`; `N`, `df`, average node-token length, and vocabulary are fitted **once on all validated nodes in that index before query filters**. The BM25 score is directional query-to-passage relevance, not symmetric document similarity. Dense retrieval uses L2-normalized pinned MiniLM chunk vectors and a query vector from the same encoder and chunk policy. Hybrid retrieval combines branch ranks with weighted reciprocal-rank fusion (`rrf_k=60`, branch weights 1 each, 20 candidates per branch in the example). The same company, accession, section, and input-version filters apply before each branch's ranking. Ties are broken by stable node ID; query rewriting is disabled. Retrieved output and the append-only local `query_log.jsonl` include ranks, score kind, filters, node IDs, source spans, and the index manifest hash.

## Reproduce a local engineering check

These commands require the separately retained, hash-matching SEC/M9 inputs and pinned MiniLM files. They do not download SEC text, use paid APIs, or run a financial experiment. In PowerShell, from the project root, choose **new** output directory names for each attempt:

```powershell
python -m pip install -e ".[embed,rag,test]"
python -m pytest -q tests/test_validated_inputs.py tests/test_rag_assistant.py tests/test_rag_eval.py tests/test_generation.py
python -m finembed.rag index --spec artifacts/m10/20261028T000807Z-loader/amzn_input_spec.json --spec artifacts/m10/20261028T000807Z-loader/googl_input_spec.json --config configs/rag_example.yaml --output artifacts/m10/<new-index-id> --dense
python -m finembed.rag retrieve --index artifacts/m10/<new-index-id> --query "Operating income" --mode hybrid --ticker AMZN
python -m finembed.rag_assistant --index artifacts/m10/<new-index-id> --query "Operating income" --mode hybrid --backend-config configs/generation_none.json --ticker AMZN
```

Omit `--dense` for a lexical-only index. In that case, `dense` or `hybrid` explicitly returns `UNAVAILABLE`; it does not fall back silently. The index command refuses an existing output directory. The retrieve command emits ranked source passages; the assistant command with `generation_none.json` returns `retrieval_only`, an empty answer field, and source-bound passages. Neither is a model-generated answer. `configs/generation_none.json` contains only `{"mode":"none"}`.

The optional development harness runs `python -m finembed.rag_eval --index artifacts/m10/<new-index-id> --questions <hash-bound-local-question-set.json> --output artifacts/m10/<new-eval-id> --modes bm25 dense hybrid --top-k 5`. Questions must identify exact saved source bytes and hashed character anchors. A hit requires a retrieved chunk that **fully contains** the anchor. The harness records per-mode denominators, misses, errors, unavailable branches, and unsupported probes. Its agent-authored labels are software-development checks, not independent human evaluation or evidence of answer quality. A smoke result should be cited only after inspecting its actual `evaluation.json`, `manifest.json`, and hashes; do not infer it from these reproduction commands.

## Generation boundary and limitations

[`generation.py`](../src/finembed/generation.py) implements `none`, `local_dense`, and `local_moe` configuration contracts. The local modes require a pinned 40-hex revision, exact local tokenizer/config/weight hashes and source receipt, declared architecture, safetensors files, and an explicit device. `local_moe` additionally checks sparse expert-routing fields; a retrieval ensemble or tool router is **not** called a neural MoE. Runtime imports and weights are loaded only when generation is invoked, with local-files-only behavior and no remote-code execution. The default `none` mode needs no generator and does not generate text. See the [separate backend assessment](M10_GENERATION_BACKENDS.md) for the verified MoE **candidate**, hardware estimate, and missing local inference evidence. A candidate model card or configured backend is not an executed generation result.

When a verified local generator is eventually available, retrieved text and explicit limitations are passed as untrusted evidence with no tool access. Generated output must parse as JSON and cite returned node IDs; malformed or unsupported citations cause abstention. This checks citation identity, **not** whether the answer is semantically correct. A conservative guard blocks generation from GOOGL MDA-1/MDA-5 chunks with unresolved sparse-header mappings, independent of question phrasing. Historical availability, exact first-public time, table-note attribution, and broader period semantics remain outside this RAG smoke. Do not use normalized dates, retrieval rank, or generated prose as financial features or trading labels without a separate approved protocol and evidence gate.
