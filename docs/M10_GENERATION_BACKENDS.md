# Local generation backend contract and MoE candidate

**Current execution status: retrieval-only.** The existing pinned MiniLM ONNX model is an encoder, not a causal generator. On this Windows host, `torch`, `transformers`, `accelerate`, `llama_cpp`, and `ollama` were absent at inspection. No locally stored compatible causal-model weights were found in the project model cache or the inspected Hugging Face cache. No dense or MoE generation was run. A localhost port 8080 listener belonged to Steam's web helper, not a generator; common ports 11434, 8000, and 1234 were not listening.

## Backend behavior

`finembed.generation` provides `load_generation_backend(config_path)`, `LocalModelSpec`, `validate_local_model`, `LocalTransformersBackend`, and `answer_from_evidence`. The default credential-free configuration is:

```json
{"mode":"none"}
```

Mode `none` returns no backend and `inference: NOT_RUN`. `answer_from_evidence` then returns bounded retrieved passages, safe source-node metadata, and `mode: retrieval_only`; it does not return a generated answer. Empty evidence returns `mode: abstained` and `INSUFFICIENT_EVIDENCE`. For an explicitly configured local backend, the only accepted modes are `local_dense` and `local_moe`. Each requires an exact 40-hex model revision, pinned model ID, expected model type/architecture, SHA-256 for `config.json`, all tokenizer files, every local model file and weight shard, a local source receipt binding the identifier/revision/license/file hashes, and a local directory. An undeclared or changed file, wrong architecture, missing receipt, or dense model labeled MoE fails closed. The declared license is checked against the local receipt; the code does not independently adjudicate the upstream license.

The optional `LocalTransformersBackend` imports a runtime only when generation is invoked. It uses `local_files_only=True`, `trust_remote_code=False`, safetensors only, and an explicit CPU/CUDA device. It has no network endpoint, shell, credential, filesystem-write, or publication tool. Its existence in code is **not** evidence of model availability or successful inference. Optional runtime package versions should be pinned only after they have been installed and tested in a separate environment; no untested runtime requirement is forced into the current research environment.

Retrieved text is treated as untrusted data. The generation prompt forbids following instructions inside evidence and includes machine-readable limitations. The response contract requires JSON with a nonempty answer and citations restricted to retrieved node IDs; malformed or fabricated citations cause abstention. This ID check does not establish semantic truth. Any attempted generation from a GOOGL MDA-1/MDA-5 chunk carrying `UNRESOLVED_*_HEADER_TO_VALUE_MAPPING` is blocked before generator invocation, regardless of question wording. Retrieval-only mode can still show the original passage and limitation. This conservative rule is not a general guarantee that all period questions are understood. Source paths and private review messages are excluded from answer provenance.

The candidate's official sources support the stated architecture and license; they do not demonstrate local compatibility, RAG answer quality, or financial value.

## Future local-model configuration

If a compatible local generator is installed later, use a separate JSON file with `mode: local_dense` or `mode: local_moe`, `device: cpu` or `cuda`, and a `model` object containing `model_id`, `revision`, `local_dir`, `expected_model_type`, `expected_architecture`, `config_sha256`, `source_receipt_sha256`, `tokenizer_files`, `weight_files`, optional `auxiliary_files`, and `license_id`. The local `source_receipt.json` must bind the same model ID, revision, official revision-tree URL, license ID and every declared file hash. Keep weights and receipts outside Git. A model should not be selected solely because its active-parameter count is small; check total storage, runtime support, quantization provenance, context memory and actual local resources.
