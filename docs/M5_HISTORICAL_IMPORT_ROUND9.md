## Source mapping before a real import

An adapter for each **actually obtained and authorized product/version** must record the product name and edition, source URL/documentation, access basis, raw file SHA-256, acquisition UTC, vintage/as-of meaning, source field names, source units, adjustment convention, identifier namespaces, date/time zones and the exact mapping to the canonical fields below. If a field is unavailable, map it to `null` with a reason; do not invent a database column or silently source it from a different vintage. Retain the raw material and adapter manifest in an ignored, access-controlled local directory. The `sources` list in a canonical bundle has `source_id`, `product`, `product_version`, `official_url`, `acquired_at_utc`, `local_file_sha256` and `access_basis`; each row cites one declared source. A structural validator cannot establish account entitlement, actual provider meaning or the truth of the source document.

| Canonical table | Required canonical fields and meaning | Unresolved source mapping or scientific choice |
| --- | --- | --- |
| `security_master` | `stable_security_id` (issue, not ticker), `firm_id`, `security_type`, `mic` (listing market), `listing_status`, `valid_from`, nullable `valid_to`, `source_id` | Map the actual product's issue/firm IDs, common-share classification, exchange and historical status/effective dates. A current ticker or current active list is not a 2020 security master. |
| `cik_security_links` | Ten-digit `cik`, `stable_security_id`, `valid_from`, nullable `valid_to`, boolean `is_primary`, dated `primary_basis` where true, boolean `ambiguity_flag`, `source_id` | Map the actual historical CIK-to-issue bridge and class/primary designation. A CIK may have concurrent share classes; neither future price availability nor realized return can choose the class. |
| `daily_bars` | `stable_security_id`, `session_date`, nullable `close`, `currency`, `price_definition`, `adjustment_basis`, `action_source_id`, nullable `missing_reason`, boolean `exit_marker`, `source_id`, `source_record_version`, `retrieved_at_utc` | Record whether close is raw/split-adjusted/total-return-adjusted, session market/time and provider vintage. A null or nonfinite price is a missing observation with a reason, not zero. A price response alone does not prove by-18:00 historical availability. |
| `actions_and_exits` | `stable_security_id`, `event_date`, `event_type`, nullable `event_value` and `event_value_unit`, nullable `terminal_price`, nullable `missing_terminal_reason`, `source_id`, `source_record_version`, `retrieved_at_utc`; an actual zero terminal price also needs `terminal_zero_evidence_id` | Preserve split, dividend, merger, delisting, liquidation and other action/exit records with raw provenance. Importing an exit or terminal price does **not** settle its label/reinvestment policy. |
| `text_evidence` | Ten-digit `cik`, `accession`, `section`, `section_sha256`, `revision_status`, `public_time_evidence_class`, nullable `public_time_utc`, `public_no_later_than_utc`, `proxy_rule_id`, `source_id`, `source_record_version`, `retrieved_at_utc` | Bind the exact accession, original/amended/corrected version, Item 1 bytes and dissemination evidence. `EXACT_FIRST_PUBLIC`, `NO_LATER_THAN_PUBLIC`, `APPROVED_PROXY` and `UNKNOWN` are distinct states. SEC acceptance alone is not the first-public instant. |

All canonical dates use `YYYY-MM-DD`; UTC instants carry an explicit offset. `valid_from` is inclusive and `valid_to` exclusive, with `null` meaning open-ended. Adjacent intervals are allowed. Overlapping intervals for the same issue or CIK/issue link are reported. Every active CIK-link interval needs a documented primary under the round-8 *proposed* rule: a single nonprimary link, a later nonprimary-only segment and concurrent links without a unique primary all fail rather than selecting an issue. Concurrent multiple primaries are also flagged. A decision-time join must use the interval containing the decision date and verify the issue's MIC/calendar applicability. An unresolved MIC or source conflict cannot be turned into a confirmed financial observation.

For each security/date required by a version-bound independent session calendar and a future event window, list `required_security_sessions`. The validator reports absent bar rows as `MISSING_SESSION_BAR` and a present row with null close as `MISSING_REQUIRED_CLOSE`; it neither advances the endpoint nor creates a price. Duplicate same-source bars and same-security/date bars from different sources are both reported; the importer must retain both raw records and a conflict ledger until an explicit source priority/version rule is reviewed. Exit events remain in the ledger even when terminal value is unknown. A zero terminal price needs affirmative source evidence; a null terminal price needs a reason. A broad-cohort result is blocked until exit outcome handling is decided separately. No data-quality rule may silently narrow the 2020 cohort to surviving or price-complete securities.

## Structural software entry point

`scripts/validate_m5_import_round9.py` accepts a JSON **canonical bundle**, returns all detected issues in a new output file and refuses to overwrite an existing report. The receipt binds the input and validator bytes by SHA-256. It checks field presence/nonempty requirements, source IDs and hash format, canonical dates/UTC, half-open interval overlap, concurrent primary claims, bar duplication/conflict, missing required sessions, invalid/null prices, exit terminal reasons and public-time evidence classes. Its output is `PASS_STRUCTURE_ONLY` or `REJECTED_STRUCTURE_ONLY`, with `admitted_financial_observations=null`, `returns_or_scores_computed=false` and `provenance_or_license_verified=false` in either case. These are software checks, not certification that a vendor product has been mapped correctly or that the M5 time/science gates passed.

```powershell
python scripts/validate_m5_import_round9.py --input <authorized-canonical-bundle.json> --output <new-local-ignored-structure-receipt.json>
```

The focused `tests/test_validate_m5_import_round9.py` fixture is explicitly `SYNTHETIC_TEST_ONLY`; it cannot be counted as a real imported security, price, filing, exit outcome or financial sample.
