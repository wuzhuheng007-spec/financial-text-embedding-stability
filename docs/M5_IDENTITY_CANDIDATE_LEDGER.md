## Inputs and unit of account

The builder uses the existing private three-file security/CIK-CUSIP candidate index and issuer-history candidate index, their saved registries and aggregate receipts. It rehashes the registered source files and saved artifacts before joining; it does not rerun either earlier CSV audit. Source files, private record locators, identifiers and row hashes remain in Git-ignored output. The [three-file intake](../reports/2026-11-11_m5_wrds_three_file_local_intake.md) and [issuer-history intake](../reports/2026-11-11_m5_issuer_history_local_intake.md) define the current source scope. The filtered Delist file, Daily rows and Distribution rows are outside this identity build; an undated Header attribute cannot establish historical market, class or primary status.

| Saved source role | Exact previously checked fields | Ledger meaning and limit |
| --- | --- | --- |
| CRSP security starting/history | `permno`, `permco`, `cusip`, `secinfostartdt`, `secinfoenddt`; other type/class/market strings remain source-qualified | Issue and issuer IDs, historical CUSIP and source history interval; no automatic eligible common share, primary listing or MIC. `hdrcusip` and ticker are not substitute join keys. |
| WRDS CIK-CUSIP observations | `cik`, `cusip`, `cusip_full`, `cikdate1`, `cikdate2`, `validated` | Exact eight-character historical CUSIP candidate; first/last filing observations and quality code, not a dated CIK-to-issue validity claim. |
| CRSP issuer history | `permco`, `issinfostartdt`, `issinfoenddt`; `issuerbegdt`/`issuerenddt` are separate fields | Same-issuer candidate and saved closed-date intersection diagnostic; issuer-history endpoint semantics are not certified as the project's half-open convention. |

The fixed node is **one retained starting issue plus one security-history source interval**, identified by stable issue ID, source role, source record and saved row digest. Two separate edge kinds attach to it:

1. **CIK observation edge:** exact historical eight-character CUSIP candidate from the saved CIK-CUSIP rows, retaining every duplicate, parallel CIK, validation code and source locator. First/last filing observations are `OBSERVATION_TIME`, never a valid-from/valid-to bridge. A unique or high-quality row remains unaccepted.
2. **Issuer intersection edge:** same issuer ID in the saved CRSP issue and issuer histories, with source row locators and the prior closed-date intersection diagnostic. It preserves zero, one and multiple issuer candidates. The supplier endpoint-inclusivity rule is unverified, so an endpoint-equality diagnostic is not a canonical half-open effective interval.

The two edge lists are joined **only through the exact source-interval node**. A Cartesian combination of a CIK observation and an issuer intersection is not asserted to be a historically valid three-way identity. Later-only issues remain separately indexed and do not enter the 2020 starting set. Each record/relation has an explicit unit; raw source rows, source intervals, candidate edges, exception records, distinct affected subjects and admitted firms are different denominators.

## Time, attributes and uncertainty

The ledger separates source observation dates, source-asserted history dates, any evidenced acquisition timestamp, the new ledger creation time and the proposed `2020-01-01` reference date. An unavailable acquisition time remains `null` or `UNKNOWN`, never replaced by the ledger creation time. It preserves saved source dates and classifies each as `VALID_TIME`, `OBSERVATION_TIME`, `ASOF_SNAPSHOT` or `UNKNOWN` only where source evidence supports that class. The logical contract allows `KNOWN`, `UNBOUNDED_WITH_SOURCE_EVIDENCE` and `UNKNOWN` boundaries, but this build must not infer an unbounded interval from a blank endpoint. End inclusivity remains `UNKNOWN` absent documented source semantics. The original security source query used an inclusive end comparison; this does not authorize silently converting every supplier interval to the project's half-open canonical interval. The issuer audit's closed-date intersection is retained as a candidate diagnostic until supplier endpoint semantics are established.

The candidate CIK valid-from/to, historical CIK-link validity, primary security, listing MIC, security eligibility and accepted status remain `null`, `UNKNOWN` or `false` as appropriate. Raw `PrimaryExch`, ticker, name, a `validated` code or an as-of upload membership cannot fill those fields. A source-identity failure rejects the build before output, whereas a true no-match is counted only after the registered sources pass identity checks. Exceptions may overlap, so the safe summary reports both per-code counts and distinct affected subjects. No row is dropped to make a count pass.

## Execution boundary and next gate

The implementation has `run` and `verify-output` entry points in [the builder](../scripts/build_m5_identity_candidate_ledger.py). `run` requires a new Git-ignored output directory; `verify-output` independently rehashes registered inputs and recomputes saved relation/exception fingerprints without constructing an Encoder. Only aggregate-safe counts and statuses may enter a report or handoff ZIP. Local private files contain the full candidate relations and source record references.

Before any formal M5 event join, establish the supplier meaning of the CIK-CUSIP observation span, evidence for time-valid CIK-to-issue identity and unique primary share, historical market/MIC and type eligibility, provider release/use scope, and the separate researcher's cohort/ambiguity choices. Unknown evidence does not become a negative match or an admitted zero-count sample.
