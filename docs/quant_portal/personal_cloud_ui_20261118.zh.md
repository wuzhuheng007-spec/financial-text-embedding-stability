## 代码核对出的迁移障碍

1. `apps/quant_portal/Dockerfile` 仅以门户目录为上下文；门户需要的仓库级 scripts/configs/results 并不自然进入镜像。
2. `compose.yaml` 的 worker 是 `manage.py run_worker`，只清理会话，不采集行情、新闻或评分；其 private 网络还是 internal。不能把它作为数据 worker 已部署的证据。
3. `scripts/quant_personal_feed/collector.py::owner_id` 直接从配置中的 SQLite 查询 auth_user；生产门户 PostgreSQL 不能沿用这个查询方式。需增加经过验证的 Django ORM/独立账户解析适配，保留 owner_id 绑定。
4. `moomoo_webapi_oauth.py::LocalTokenStore` 使用 Windows DPAPI。Linux 上应通过供应商允许的重新授权与服务端密钥存储适配实现，不要上传聊天密钥或直接复制不可解密文件，更不能通过换机器规避 HTTP 439。
5. `news_sentiment_factor_v45/worker.py` 顶层导入 msvcrt，锁实现仅 Windows；需实现 Linux fcntl 适配并检查单实例与进程身份。v42 和 v45 要由系统服务管理器启动前台 run 入口。
6. 私人原件、证券映射、模型权重、研究数据库不在 GitHub。需从本机安全迁移，保留来源时间与哈希。镜像不打包凭据和用户数据库。
7. Django PostgreSQL 迁移与行情/研究 SQLite 是两回事。个人单实例可先保留本地磁盘上的 WAL sidecar，但必须补做并发与锁恢复测试；不能放网络共享盘，不能因门户用了 PostgreSQL 就宣称所有数据库均已迁移。

## 采购参考（未下单）

阿里云国际站公开轻量服务器 Linux 套餐表列出：2 vCPU/4 GB/80 GB SSD 为 USD 19/月；2 vCPU/8 GB/160 GB SSD 为 USD 35/月。来源：https://www.alibabacloud.com/en/product/swas/pricing （2026-11-18 查询）。

个人试点优先按 2 vCPU/8 GB 估算，先测 CPU FinBERT 的内存、队列延迟，再决定是否升配；这不是性能保证。暂不租 GPU，也不承诺这台规格能服务数百人。地域、库存、账户站点、税费、备份、超额流量、域名与模型 API 费用以实际订单和用量为准。不能把国际站标价当作阿里云中国站固定报价。

部署前先验证选定地域下两个数据源的正常接入条件，再让用户确认具体地域、套餐、总价与续费安排。若更强模型需要新 API 付费，应先列单独预算，不在后台无限重试。

## 给本机 Codex 的执行步骤

### P0 读取现场
1. 读取仓库当前 HEAD、工作区改动与本文件。不要重置或覆盖无关改动。
2. 先读取已安排的 05:17 只读回执及 v4.3 数据库，记录首个快照实际是否存在、实际可用时间、覆盖缺口和队列。已过截止不等于已成功发布，不补造。
3. 对账户、行情、分析、研究、标签数据库做在线备份并回读。保存进程与连接状态。
4. 在隔离 worktree 检查本分支；有冲突按实际当前代码合并，不覆盖最新研究回执。

### P1 应用和验收页面
1. 应用本分支页面与锁恢复改动，检查原账户、自选、设置、事实卡保持一致。
2. 运行本分支指定测试；运行实际开发/生产依赖，不直接采用其他环境版本。
3. 登录后检查中文、英文各桌面和 390px：四入口切换、行情曲线、事件跳转、筛选、自选订阅、来源链接、原文展开、自动刷新不丢阅读位置。
4. 日志、旧版本和研究缺口只留在研究/运行页。重要的过期报价、采集中断与来源归因仍要简短可见。
5. 新版脚本版本已更新；首次刷新旧页面后再验收。

### P2 恢复真实采集
1. 保存 Jin10 锁错误日志；升级后核对异常栈文件/函数/行号，识别具体写入操作，不把资源释放修复宣称为已定位原始锁持有者。
2. 在避开研究快照提交的窗口切换采集进程。确认旧实例退出后才启动新实例，避免重复订阅和重复供应商调用。
3. 检查金十真实新成功响应、实际写入、去重及分页衔接；并验证 moomoo 推送继续到达。
4. 注入一次本地锁冲突，确认有限间隔退避后恢复；认证失败和安全策略错误不得无限重试。
5. 439 端点仍暂停，使用已授权的官方支持路径处理。dot 没有独立必要性，不为填满页面而接入。

### P3 处理可用分析而非虚假完成
1. 逐一核对新闻 item_key、content_sha256、版本与中文评分记录的匹配关系；只接入确切版本的有效评分，不用同公司另一条新闻的分数填空。
2. 为关注榜事件展示简短原文摘要、主体、事件性质和来源。指控、预测、发言必须保留归因；证实有原报道不等于主张成立。
3. 如有已配置且获准使用的生成服务，对固定小批次执行摘要、条件性影响、反向情景、后续观察指标；保留证据句、模型版本、生成时间和费用。暂停队列不能未经检查直接恢复。
4. 本轮 UI 不负责为未通过内容检查的草稿放行。没有模型配置或内容不过关，明确列为未完成；不把模板式“关注后续公告”当成完成了 AI 分析。
5. 英文原文翻译要单独检查数字、人名、否定词和发言归因；原文始终可展开。禁止把文本正面度称作上涨概率。

### P4 完成 Linux 部署版本
1. 解决上述镜像上下文、账户数据库适配、DPAPI、msvcrt 和私人文件路径障碍。
2. 明确拆分 web、moomoo、金十、中文评分、日度快照/标签与价格任务的运行入口及唯一实例锁；一个数据源故障不得终止另一个。
3. 配置服务自动启动、失败退避、磁盘日志轮转、业务成功时间监控、日度备份与恢复。心跳不能代替业务成功。
4. 保留供应商配额、评分预算、前瞻可用时间规则与历史污染期约束。迁移采用单写入者切换，本机和云端不能同时写同一条前瞻流水。
5. 完成容器构建和隔离联调后，再提供准确的阿里云购买页面、地域、费用和需要用户完成的实名/付款/授权步骤。不要先购买尚不能运行的整套配置。

### P5 云端验收
1. 通过安全连接取得服务器访问，不在聊天或 Git 中写密码、令牌、私钥。配置域名 HTTPS，数据库不暴露公网，仍为所有者私用。
2. 迁移数据库与模型文件后核对行数、身份、源哈希和原有账户；执行数据库恢复演练。
3. 用户电脑断网或关机后，用另一设备读取云页面；观察云端新行情、新新闻及评分实际推进，而非只检查 HTTP 200。
4. 重启云服务器检查服务恢复；确认下一次自然日度截止自动发布。未到期收益标签继续等待，不能补造。
5. 回滚时先停止云端写入，再恢复本机唯一采集实例。保留云端已形成的前瞻记录，不回拨来源时间。
